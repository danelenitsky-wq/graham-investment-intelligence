## Verdict

**Ready for single-user production use for US stocks, with conditions**,
after the fixes in this branch: run it behind `APP_PASSWORD` and HTTPS,
single process, with the free providers listed below. Core Graham
calculations were recomputed independently from raw SEC filings for MSFT,
NVDA and GOOGL and match to the last digit. Live integrations with SEC
EDGAR, Tiingo and Finnhub were verified with real responses. Twelve Data is
**BLOCKED** (no key) and FMP Basic is **not tested** (no key). PR #7 is not
covered by the real-data run (see section 5).

Before these fixes it was **not** ready: anyone who could reach the server
could read and change the portfolio and spend the API quotas, the default
Graham growth-formula value inflated all three test companies, and the price
chart showed NVDA and GOOGL as having fallen 41% and 91%.

Decision engine checks (code review plus unit tests):

- No confident Buy from stale or missing data: **PASS**. Missing, stale, conflicting, fixture data or a historical-only price all make data quality CRITICAL → INSUFFICIENT VERIFIED DATA before any other category; BUY CANDIDATE only after the gate passes, and any caveat lowers confidence to LOW.
- No fabricated intrinsic value: **PASS** in the decision engine (uses only an ESTABLISHED model value). **Was FAIL** on the valuation page (F2), fixed.
- No automatic Sell from a price decline: **PASS**. No rule compares price with cost; REVIEW FOR SALE needs a failed business rule, deteriorated fundamentals, an excessive valuation or concentration.
- FAIL vs NOT_APPLICABLE vs INSUFFICIENT_DATA: **PASS**. Banks get D1/D2/E1/E2/E7 NOT_APPLICABLE, REITs whole screens NOT_APPLICABLE, missing inputs INSUFFICIENT_DATA (from the earlier real run on JPM and O, and unit tests).
- ETFs: classified NOT_APPLICABLE for company criteria (main); PR #7 adds ETF-specific metrics.
- Growth companies: classified as industrial and judged by the same rules; the AVOID results are strategy-relative and the report says so.
- Note (design, not a bug): the decision card lists only business-rule failures (D2/D4); price-rule failures (D6, D7) are deliberately shown on the strategy card and as WAIT reasons, so the two cards show different counts.

## 9. Historical analysis

- Decision snapshots store the inputs, their hash, filing accessions, price date, quote status and timestamp (`src/lib/decision/snapshot.ts`); the real run wrote one per stock. Retrieval times are excluded from the hash so an unchanged refresh does not create a new version.
- **No backtesting exists, and none should be added on this data**: there is no point-in-time fundamentals dataset (statements as known on each date, before restatements and split restatements). This is now stated in README and `docs/DEPLOYMENT.md`.

## 10. Remaining risks and missing coverage

- Statement figures come from one source (SEC). The independent cross-check needs a free FMP Basic key (5 years) and is otherwise SKIPPED; the decision data-quality factor shows "not cross-verified".
- Free quotes are end-of-day or delayed. Nothing is real time.
- No IFRS (20-F/40-F) filers, no TASE fundamentals, no TTM statements.
- companyfacts omits dimensional facts (per-class shares, segments).
- `npm run test:integration` needs `DATABASE_URL` exported in the shell (it does not read `.env`, which also protects a real database from the test writes). Documented, not changed.
- Rate budgets are per process; running several instances can exceed free limits.
- Single user; no audit log of who changed what.
